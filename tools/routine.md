다방 부평권 월세 매물을 수집해 ① GitHub Pages(index.html) 갱신 ② 카톡 전송용 HTML 전달 ③ 아티팩트 갱신까지 한다. 스케줄 실행이라 질문 없이 끝까지 가고, 매물 문의·전송 같은 write 액션은 절대 하지 마라. 채팅 요약은 반말로 짧게.

작업 폴더: 이 저장소 루트. 루틴 세션은 이 폴더에서 열린다. (origin=git@github.com:9503chl/DabangSearcher.git, 공개 주소=https://9503chl.github.io/DabangSearcher/)

## ★승인창 없이 끝내는 게 핵심
무인 실행이라 승인창이 하나라도 뜨면 사람이 볼 때까지 몇 시간씩 멈춘다(2026-09-30·10-01 실제로 4~5시간 멈춤). 허용된 건 아래뿐이니 **이것 말고는 아무것도 부르지 마라.** 확인용 `ls`·`cat`·`node -e`·`git status` 도 안 된다.
- Bash: `bash tools/routine.sh` — 정확히 이 문자열. `cd`·파이프·인자를 붙이면 허용 규칙에서 벗어난다.
- Artifact (read / publish)
- SendUserFile
- ToolSearch → `mcp__ccd_session_mgmt__archive_session`

## 1. 스크립트 한 번
`bash tools/routine.sh` 하나가 origin 동기화 → 수집(`tools/collect.js`) → 검증 → 카톡·아티팩트용 사본 → 커밋·푸시까지 다 한다. 1분 안팎.
- 끝에 `■ 요약` 이 나오고, 카톡 파일과 아티팩트 사본의 절대경로를 찍는다.
- `✗ 실패:` 로 끝나면 우회하지 말고 그 줄과 직전 로그를 요약해 보고한 뒤, 아티팩트·아카이브 없이 멈춰라.

## 2. 카톡 파일
요약의 `카톡` 경로를 `SendUserFile` 로 보낸다(status: proactive). index.html 은 외부 리소스가 없는 자체 완결 문서라 오프라인·아이폰 사파리에서 그대로 열린다.

## 3. 아티팩트
URL: https://claude.ai/code/artifact/b189221c-fca7-4932-88ad-a059ba101691 (제목 "Dabang Monthly Rent Bupyeong"). **새로 만들지 마라. URL 이 바뀌면 안 된다.**
- 먼저 `action:"read"` 로 라이브 본문을 읽는다. 안 읽고 publish 하면 거부된다(2026-08-28 왕복 2회 낭비).
- DATA 블록(`<!-- DATA:START -->`~`<!-- DATA:END -->`) 밖이 평소 템플릿과 다르면 누가 페이지에서 저장한 변경이다. 덮어쓰지 말고 보고만 해라.
- 괜찮으면 요약의 `아티팩트` 경로를 `file_path`, 위 주소를 `url` 로 publish. 제목은 스크립트가 이미 바꿔 뒀다.

## 4. 요약 → 아카이브
반말로 3~4줄: 노선별 건수, 신규(있으면 역·가격), 커밋 해시, 상세 파싱 실패 같은 경미한 건.
그다음 **맨 마지막에** ToolSearch `select:mcp__ccd_session_mgmt__archive_session` 로 툴을 불러와 `session_id:"self"` 로 호출한다. 이 툴이 반환되면 대화가 끝난다.
- 사이드바에 매일 세션이 쌓이는 걸 막기 위한 것이다(2026-09-26 사용자 요청).
- ★실패(스크립트 실패·푸시 실패·아티팩트 거부)가 있으면 아카이브하지 마라. 남아 있는 세션이 곧 "확인 필요" 신호다. 상세 파싱 1~2건 실패 같은 경미한 건은 요약에 적고 아카이브해도 된다.
- `delete_session` 은 절대 쓰지 마라.

## 참고 — 스크립트 내부 (로직을 손볼 때만)
- 로직을 고쳤으면 먼저 `bash tools/routine.sh --dry` 로 돌려라. `.collect-dry/` 에만 쓰고 git 은 안 건드린다.
- 5개역: 부평(1호선) / 간석오거리(인천1) / 인천시청(인천1·2 환승, 별도 섹션) / 모래내시장·만수(인천2).
- 필터: 월세, 보증금 200~2000만, 월세 60만 이하, 단기 제외, 오픈형 원룸 제외. 다방 API 가 400 이면 `user-agent` 헤더 문제다.
- 건축물용도: 공동주택·단독주택만 통과. 근생·숙박·업무·오피스텔은 전입신고가 안 되는 경우가 대부분이라 상세로 거른다.
- 방 구조: 상세 '방종류' 가 `원룸(분리형)`→1.5룸(분리형), `아파트(분리형)`→1.5룸(아파트). 그냥 `원룸`은 오픈형이라 탈락. 결과물에 '원룸' 이라는 낱말이 남으면 안 된다(스크립트가 검증).
- 정렬: 보증금 내림차순 → 사용승인일 최신순 → 월세 낮은 순, 노선별 상위 8건. 태그: NEW / 북향 / 서향 / 꼭대기층 / 1층 / 반지하.
- 동일 매물(가격·승인일·층·방향이 같은 별개 id)은 하나로 줄이되 이미 실렸던 쪽을 살린다.
- `data/seen.json`: `accepted`(상세 캐시) / `excluded`(용도 미달, 영구 제외) / `shown`(페이지에 실린 적 있는 id). NEW 기준은 `shown` 이다. `accepted` 로 잡으면 처음 보는 매물이 '기존'으로 찍힌다(2026-08-26 12건 오판정).
- index.html 은 DATA 블록만 교체한다. 레이아웃·CSS·스크립트, 특히 신규 표식(`.card.is-new`, `.newmark`)과 「간택 범위」 가리개(`#switch`)는 사용자가 요청해 넣은 것이라 건드리지 마라.
