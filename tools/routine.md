작업 폴더: 이 저장소 루트 — 루틴 세션은 이 폴더에서 실행된다 (git repo, origin=https://github.com/9503chl/DabangSearcher.git, 공개 주소=https://9503chl.github.io/DabangSearcher/)

## 수집 — `tools/collect.js` 하나로 끝난다

★수집·판정·정렬·index.html 갱신·원장 누적이 전부 스크립트에 들어 있다. **직접 브라우저를 몰지 마라.** 2026-08-26 이전엔 내장 브라우저로 map+pushState 트릭을 썼는데 스테일 DOM·CDP 타임아웃·탭 정리 때문에 매 실행 사고가 났다. 지금은 Playwright 가 `/room/{id}` 를 직접 연다(매번 새 navigation 이라 스테일 DOM 이 구조적으로 불가능).

```bash
cd "<이 저장소 루트>"
npm install                        # 최초 1회 (playwright)
npx playwright install chromium    # 최초 1회
node tools/collect.js
```

- 30~60초면 끝난다. 원장에 상세가 캐시돼 있어 재실행일수록 빨라진다.
- `--dry` 를 붙이면 `.collect-dry/` 에만 쓰고 원본을 안 건드린다. 로직을 손봤을 땐 먼저 이걸로 돌려 기존 산출물과 비교할 것.
- `--budget N` 은 **노선당 상세 클릭 상한**(기본 30). 채택 수가 아니라 클릭 수만 제한한다 — 채택 수로 끊으면 보증금이 낮아 아래에 묻히는 1.5룸·신축을 영영 못 찾는다.
- 스크립트가 실패하면 우회하지 말고 그 사실을 채팅에 보고할 것. API 가 400 이면 `user-agent` 헤더 문제다(다방이 UA 없는 요청을 막는다).

### 스크립트가 이미 하는 것 (다시 손으로 하지 마라)
- 5개역: 부평(1호선) / 간석오거리(인천1) / 인천시청(인천1·2 환승, 별도 섹션) / 모래내시장·만수(인천2)
- 필터: 월세, 보증금 200~2000만, 월세 60만 이하, 단기 제외, 오픈형 원룸 제외
- ★건축물용도 판정: 공동주택·단독주택만 통과. 근생·숙박·업무·오피스텔은 전입신고가 안 되는 경우가 대부분이라 반드시 상세로 거른다.
- ★방 구조: 상세 '방종류' 가 `원룸(분리형)`→**1.5룸(분리형)**, `아파트(분리형)`→**1.5룸(아파트)**. 그냥 `원룸`이면 오픈형이라 탈락. **결과물에 '원룸' 이라는 낱말이 남으면 안 된다.**
- 정렬: 보증금 내림차순 → 사용승인일 최신순 → 월세 낮은 순. 노선별 상위 8건만 싣는다.
- 태그: NEW / 북향 / 서향 / 꼭대기층 / 1층 / 반지하
- 동일 매물(가격·승인일·층·방향이 전부 같은 별개 id = 다른 중개사가 올린 같은 집)은 하나로 줄이되 **이미 실렸던 쪽을 살린다.** 안 그러면 같은 집이 매번 신규로 튄다.

## `data/seen.json` 원장

키는 `accepted` / `excluded` / `shown` 세 개다.

- `accepted[].detail` = 상세 필드 캐시. 있으면 재클릭하지 않는다. `struct` 는 `ok`(표시 대상) 또는 `open`(오픈형 원룸, 영구 표시 제외).
- `excluded` = 용도 미달(근생/숙박/업무). 영구 제외.
- ★`shown` = **페이지에 실린 적 있는 id**. `NEW` 태그 기준은 이것이다. `accepted` 기준으로 잡으면 안 된다 — 원장엔 상세만 열어보고 페이지엔 한 번도 안 실린 매물이 잔뜩 쌓여 있어서, 사용자가 처음 보는 매물이 '기존'으로 찍힌다(2026-08-26 실제 발생: 12건 오판정). 기준은 "원장에 있었나"가 아니라 "내 목록에서 본 적 있나"다.

## index.html 템플릿

`<!-- DATA:START -->` ~ `<!-- DATA:END -->` 사이만 스크립트가 교체한다. **레이아웃/CSS/스크립트는 건드리지 마라.** 특히 아래는 사용자가 요청해서 넣은 것이니 지우지 말 것:
- 신규/기존 구분 — 신규 카드는 푸른 옥테 + 왼편 `新` 표식 (`.card.is-new`, `.newmark`)
- 상단 「간택 범위」 가리개 (`#switch`) — 전체 / 새로 든 것 / 전부터 있던 것
- 이 UI 는 `listings[].tags` 의 `"NEW"` 하나로 구동된다.

교체 후 `node -e` 로 DATA 블록 JSON 이 파싱되는지, `#switch`·`.card.is-new`·`newmark` 가 그대로 있는지만 확인하면 된다. 브라우저로 열어볼 필요는 없다.

## 산출물 3 — 아티팩트 갱신
URL 은 https://claude.ai/code/artifact/b189221c-fca7-4932-88ad-a059ba101691 (제목 "Dabang Monthly Rent Bupyeong"). Artifact 툴 `url` 파라미터에 이 주소를 넣어 덮어쓸 것. **새로 만들지 마라(URL 이 바뀌면 안 된다).**
index.html 을 그대로 올리면 `<title>여왕 폐하의 간택 목록</title>` 때문에 아티팩트 이름이 바뀌니, 스크래치패드에 복사해 `<title>` 만 `Dabang Monthly Rent Bupyeong` 로 고쳐 올릴 것. URL 이 죽어 있으면 `action:"list"` 로 다시 찾아라.

★덮어쓰기 전에 `action:"read"` 로 라이브 본문을 먼저 읽어라. 안 읽고 publish 하면 "라이브 버전을 본 적 없다"며 거부당하고, 저장된 사본을 전부 Read 한 뒤 URL 을 한 번 더 fetch 해야 통과된다(2026-08-28 실제로 왕복 2회 낭비). 읽은 뒤엔 라이브와 새 파일을 diff 해서 DATA 블록만 다른지 확인하고 올릴 것 — 페이지에서 누가 저장한 변경이 있으면 그건 병합 대상이지 덮어쓸 대상이 아니다.

## 마무리 — 커밋 & 푸시
`git add index.html data/seen.json && git commit && git push origin main`.
커밋 메시지는 한 줄 요약 + `-` 리스트(번호 리스트 금지), 이번 실행 스코프만:
```
다방 부평권 매물 갱신 YYYY-MM-DD
- 1호선 N건 / 인천1호선 N건 / 인천1·2호선 N건 / 인천2호선 N건
- 신규 M건, 용도 탈락 K건 누적
```
푸시가 인증으로 실패하면 우회하지 말고 그 사실을 채팅에 보고할 것.

## 뒷정리 — 이 세션 아카이브
채팅 요약을 출력한 뒤, 마지막으로 `mcp__ccd_session_mgmt__archive_session` 에 `session_id:"self"` 를 넘겨 이 세션을 아카이브하라. 이 툴이 반환되면 대화가 끝나므로 반드시 맨 마지막에 호출할 것.
- 매일 세션이 하나씩 쌓여 사이드바가 지저분해지는 걸 막기 위한 것이다 (2026-09-26 사용자 요청. 그때까지 33개가 방치돼 있었다).
- ★**실패했으면 아카이브하지 마라.** 수집 실패·푸시 인증 실패·아티팩트 거부 등 사용자가 봐야 할 게 남았으면 세션을 살려둬야 한다. 사이드바에 남아 있다는 것 자체가 "확인 필요" 신호가 되도록 하는 게 이 규칙의 핵심이다.
- 상세 파싱 1~2건 실패처럼 결과에 영향 없는 경미한 건은 요약에 적고 아카이브해도 된다.
- 아카이브는 되돌릴 수 있다(사이드바 Archived 에서 복구). `delete_session` 은 절대 쓰지 마라.
